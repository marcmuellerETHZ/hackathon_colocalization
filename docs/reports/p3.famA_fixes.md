## 1. What changed (`src/famA/joint_susie.py`, `src/famA/method.py`)

| P3-5 item | Implementation | Default |
|---|---|---|
| 1 Multi-start IBSS | Each locus is fitted from two starts: the default start, and a "no-shared-first" start (π_both = 0 and the other states renormalised for the first 5 sweeps; π-EB and convergence are suspended during that phase, and the ELBO trace restarts after it). Both starts are rows of the same GPU batches, and the fit with the higher final ELBO is kept. `extra` records `start` and `elbo_starts`. | `multistart=True` |
| 3 η floor | `eta_floor=1e-3` on all rungs. Rungs without η estimation use a fixed η of 1e-3; the η Brent's lower bound is max(1e-8, floor). | on |
| 4 Stopping | Rule `rel`: stop if ΔELBO < 1e-3, or \|ΔELBO\| < 1e-6·\|ELBO without the π log-prior\|, or max\|Δα\| < 1e-4. Layer E keeps the `alpha` rule. | `convergence="rel"` |
| 2 Per-trait LD (L0) | The mean map is blockdiag(R̃₁, R̃₂) when the locus has `R2`/`X_ref2` of the same kind; the SER is unchanged. η terms: log\|R̃₁\| + log\|R̃₂\| and [z̃₁ᵀR̃₁⁻¹z̃₁ + z̃₂ᵀR̃₂⁻¹z̃₂ − ρ z̃₁ᵀ(R̃₁⁻¹+R̃₂⁻¹)z̃₂]/(1−ρ²). This is exact for ρ = 0 and for R₂ = R₁; otherwise it is an approximation (README 21). Loci without a trait-2 LD use one R. | `per_trait_ld=True` |
| 5 Own-effect guard | Already the default (`nonweak_own=True`). The module docstring now says so; `nonweak_own=False` gives the μ-only option. | on |
| P3-6 π | EB with κ = 4 is the default; `pi_mode="fixed"` (π = ¼ each) is the sensitivity option. | EB |

**Ablation ladder for the Method API:**
- `famA.method.LADDER = ("base", "+rho", "+eta", "+E", "+multistart", "+perTraitLD")`. The rungs are cumulative.
- Build a rung with `ladder_config(rung, pi_mode, nonweak_own)` or `ladder_method(...)`.
- A rung can also be a list of components, e.g. `rho+eta+multistart+perTraitLD` for the ladder without layer E.
- Method names: `famA_joint_susie`, `_rho`, `_rho_eta`, `_rho_eta_E`, `_rho_eta_E_ms`, `_rho_eta_E_ms_ptld`. The suffixes `_pifix`, `_numu` and `_floor0` mark the options.

**Review items folded in:**
- **Layer-E table v2** (`ref_ld_var@v2`, job `famA_refldvar_v2`, 0.7 min CPU).
  - It uses the same windows and draws as v1, but draws where a pair has a subsample-monomorphic variant are excluded.
  - Common-pair cells are identical to v1. Rare pairs (min MAF < 0.05) change as follows:
    - r² 0.8–0.9: 1.90 → 1.03
    - r² 0.9–0.95: 1.04 → 0.38
    - r² ≥ 0.995: 0.89 → ≈ 0
    - r² 0.3–0.5: 2.49 → 2.19
  - v2 is now the default (`REF_VAR_TABLE`). The lookup convention is documented: the table is binned by pool r² but looked up by reference r̂².
- **G identity, float32 next to float64** (from the review's job `p2rA_g_identity`, 24 fits): float64 max |ΔPIP| 4.0e-8 (24/24 niter equal); float32 max |ΔPIP| **6.2e-4** (dense 2.0e-7; 23/24 niter equal), which is under the 1e-3 gate. The float32 margin comes from a non-converged L2 factor locus.
- **R identity gates now fail instead of skipping inside orch jobs.** `has_r` raises `pytest.fail` when `ORCH_JOB_ID` is set, in the famA and famG conftests, and the mvsusie test now uses `has_r`.

**Identity configs:** the identity tests and `compare_mvsusie.py` set `eta_floor=0, multistart=False` explicitly. DESIGN defines the identity at η = 0, and mvsusieR has a single start. Tolerances are unchanged. `test_eta_detects_reference_mismatch` now expects the in-sample η to be at the floor (it was < 1e-3), and it adds a floor-0 check that η is still < 1e-3.

## 2. Tests (`tests/famA/test_p3_fixes.py`, 10 tests)

All tests: job `famA_p3fix_tests_r5` @ fb8dfb0, `pytest tests/famA tests/famG` → **49 passed, 0 skipped** (R identity gates ran: G vs susieR float64/float32, A vs mvsusieR, coloc, Brent).

The new tests check:
- Multi-start never returns a lower ELBO than the single start, and its default start equals the single-start fit.
- The no-shared phase zeroes the 'both' mass, which returns after the phase.
- η floor on a toy where two reference-identical columns (n_ref = 40) differ in the study:
  - η = 0 diverges: σ² reaches e¹⁵ and the ELBO grows by more than 100 per sweep.
  - η = 1e-3 stays bounded with shrinking increments.
  - Estimated η converges.
- `rel` never takes more sweeps than `susie014`, and the PIP difference is < 1e-2.
- Per-trait LD with R₂ = R₁ reproduces the one-LD fit (dense and factor, ρ = 0.35, η estimated). Agreement: PIP to 1e-6, and the ELBO trace.
- Per-trait η terms match a brute-force calculation at ρ = 0 with R₁ ≠ R₂.
- Ladder names and configs.
- v2 table vs v1.

**Honest limit of the η floor** (CPU scan, same toy, 200 sweeps, Δz = 6–9):

| η | Behaviour |
|---|---|
| 0 | ELBO +260–550 per sweep |
| 1e-3 | Still +5–10 per sweep, σ² ≈ e¹³ |
| 1e-2 | Converges in ≈ 60 sweeps |

The floor makes the likelihood proper, but the base and +ρ rungs remain poor fits on rank-deficient LD. In such loci the `rel` rule's α part stops them while the ELBO is still rising.

## 3. Validation-only smoke (job `famA_p3fix_smoke_r1` @ bc9e492; artifact `famA_p3fix_smoke@v1`)

- **Loci:** 300 loci, 60 per cell from L0|P3|rho=0.5, L2|P1, L2|P3, L4|P1 and L4|P3 of screen_v2 (seed 20261027), with p = 667–6,225.
- **Timing:** wall time after a warm-up, on the GPU shared with other jobs.
- **Commit:** bc9e492 predates the v2 table (affects only E, not run here) and the π-prior-free rel scale (κ = 4 term ≈ 5 nats; negligible).

| Rung | loci/s | failed | non-converged | median / max sweeps | noshare start kept |
|---|---|---|---|---|---|
| `+eta` (single start) | 1.67 | 0 | 1 (L0\|P3) | 10 / 100 | – |
| `rho+eta+multistart` | 1.66 | 0 | 0 | 12 / 91 | 114 / 300 |
| `rho+eta+multistart+perTraitLD` | 2.00 | 0 | 0 | 12 / 91 | 114 / 300 |

- **Cost of multi-start:** about 1.0× wall time at these batch sizes (the GPU is under-used, so the second start runs in the same batches). The worst case is 2× the IBSS rows and η spectra.
- **ELBO gain from the second start** (noshare minus default):
  - gain > 1 nat on 62 / 300 loci;
  - up to 374 nats in the L2/L4 cells;
  - lower on 183 loci (the default start is kept there).
- **Effect on scores:** keeping the better start changed P_S by more than 0.1 on 21 loci and P_D by more than 0.1 on 18 loci.
- **Per-trait LD was not exercised:** among the non-A1 screen_v2 cells, none stores `R2` (L0|P3 has only `R`). The third row is therefore the one-LD fit, and its speed difference is run-to-run noise.

## 4. Decisions needed (with my recommended default)

1. **The shared reader and harness do not load `R2`/`X_ref2`, so A1 run through the harness would silently use one LD** (`extra.per_trait_ld=false`). I reverted my edit of the eval-owned files at the PI's request. The exact change:
   - `eval/io.py`: add `R2`/`X_ref2` (default None) to `LocusData`; add `load_ld2=False` to `_read_group`/`LocusSetReader.read`, loading `g["R2"]`/`g["X_ref2"]` when it is set.
   - `eval/harness.py:111`: pass `load_ld2=getattr(m, "needs_ld2", False)`. JointSusieMethod sets `needs_ld2`.
   - Workaround on the famA side: `famA.method.attach_ld2(set_path, loci)`.
   - **Default:** merge that opt-in reader change before A1.
2. **Per-trait LD was never tested on real loci.** **Default:** run A1 with `+perTraitLD`, as approved in P3-5, and also report the one-LD `rho+eta+multistart` rung.
3. **Primary A configuration for A1. Default:** `rho+eta+multistart+perTraitLD` with π EB (κ = 4), without layer E. E stays an ablation rung, now on table v2.
4. **Stopping rule. Default:** keep `rel` as approved. Caveat: its α part stops diverging η-free rungs early (§2).
