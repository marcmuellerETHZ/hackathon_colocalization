## Methods (what ran)
1. **Benchmark.** Job `p9_bench_m4_main_full` (5.3 min, 8 cores):
   `scripts/baselines_p4.py bench --ids-file results/baselines_m4/m4_subsample_v1/main.txt --reuse-from results/baselines_m4/runs ... --unit block --n-boot 2000`.
   - It covers all existing M4 runs.
   - coloc_susie and coloc_susie_mm are each merged from their two disjoint half runs (`extra_runs`, the df23941 mechanism).
   - Failures are scored least-favourably, with a 2,000-replicate BCa bootstrap over LD blocks and the strength-only control cross-fit with K = 5.
   - Bench dir: results/baselines_m4/bench_p9/benchmarks/20261028T084150Z_p9_m4_main_full.
2. **OP fits.** New subcommand `scripts/baselines_p4.py op2`.
   - OP1 comes from the same call as run_benchmark (`run_benchmark._op_points` → `metrics.matched_w_thresholds`).
   - OP2 comes from `eval.op2.op2_thresholds`.
   - Each method is fitted on its own loci, with least-favourable failures, in the run_benchmark main setting ("realistic": M4 cells L1–L6; screen_v2 cells L2+L4).
   - Jobs: `p9_op2_screen_v2_r2` and `p9_op2_m4_main` (main.txt ids; colocboost/colocboost_m1 on slow.txt ids).
   - `scripts/baselines_p4.py opfinal` then assembles the phase-2 operating-point file.
3. **OP2 implementation:** `src/eval/op2.py`. See "Decisions needed" 3 for why it is not in metrics.py.
   - It uses only public metrics building blocks (`dw_weights`, `sd_weights`, `matched_threshold`, `_gate`), and no existing metric code changed. `src/eval/metrics.py` is byte-identical to its frozen sha256 192f3c42….
   - Rule:
     - t_S = max(t_W, t_D), where t_W is the weighted matched-W threshold (2.5%, OP1 weights) and t_D is the unweighted threshold on power-matched D (10%).
     - Both rates fall monotonically in t, so this max is the smallest t that satisfies both.
     - If the smallest feasible t is > 1, then t_S = 1, `op2_feasible = false` and no S calls are made (`t_S_call = inf`).
     - t_D is then fitted as in OP1, with S precedence at the OP2 S rule.
   - "Power-matched D loci of the fit set" = class D with S-vs-D weight > 0 in the fit setting. That is 2,678 D loci on M4 (22 realistic D loci fall in power bins without S) and 4,000 on screen L2+L4.

## Decisions needed (recommended defaults)
1. **coloc_susie_mm M4 = the existing phase-1 half runs** (wrapper and harness unchanged since df23941), with no re-run. *Default: accept.*
2. **Encoding of "t_S = 1" in test_methods_v2.yaml.** The call rule is P_S ≥ t_S, so a literal 1.0 would still call S at P_S = 1.0, and those loci are exactly what makes OP2 infeasible (SharePro).
   - *Default:* freeze OP2-infeasible methods with t_S = 1.0000000000000002 (just above 1 = no S calls, the form used for mvSuSiE in phase 1), and record `op2_feasible: false`. This counts as "t_S = 1" for B-mm rules (c)/B1 (FAIL).
3. **OP2 lives in `src/eval/op2.py`, not in metrics.py**, because metrics.py is hash-protected (configs/FROZEN_SHA256); adding a function there would change its sha256. *Default: accept, and add src/eval/op2.py to FROZEN_P2_SHA256.*
4. **"Power-matched D loci of the fit set" = class D with S-vs-D weight > 0 in the fit setting** (unweighted share). *Default: accept.*
