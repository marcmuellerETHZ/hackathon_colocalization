## 1. What was built

### Family G — GPU coloc-SuSiE (engineering baseline)
- `famG/susie_rss.py`: batched GPU SuSiE-RSS that reproduces **susieR 0.14.2 `susie_rss(z, R, n, L = 10)`** (and the no-`n` path): PVE-adjusted z, standardisation, prior weights with susieR's `log(1/p + √ε)` quirk, per-effect prior variance by **exact port of R's `Brent_fmin`** (same bracket, tolerance, keep-old rule and null check; EM and none also available), check_prior, ELBO convergence (0.14.2 rule, tol 1e-3, max_iter 100), credible sets exactly as `susie_get_cs` (V > 1e-9, de-duplication over all rows, purity min |r| ≥ 0.5 from cov2cor(XtX), purity ordering), PIP with prior_tol.
- Dense R `(B,P,P)` or genotype-factor X `(B,n_ref,P)` LD (`famG/ld.py`); loci bucketed by p (p_max ≤ 1.1·p_min, 6 GB LD budget per bucket, padding variables have prior weight 0 → exactly zero mass); batch compaction as loci converge.
- Precision: all non-LD arithmetic in float64; LD products in float32 (default) or float64; TF32 disabled and asserted (`famG/precision.py`).
- `famG/ser_kernel.py`: one fused **Triton kernel** does the whole Brent prior-variance optimisation for all loci of a batch (one program per locus); this replaced ~2,400 small kernel launches per SER and gave a ~10× speed-up.
- `famG/coloc.py`: GPU `combine.abf`, `coloc.bf_bf` (batched over loci and all CS-pairs), coloc.abf ABFs.
- `famG/method.py`: `GPUColocSusie` Method (INTERFACES §4) = SuSiE per trait → bf_bf over CS effects (p12 = 5e-6) → DESIGN §4.3 adapter via `eval.adapters.coloc_susie`, coloc.abf fallback when a trait has no CS.

### Family A — JointSuSiE
- `famA/joint_susie.py`: batched GPU bivariate SuSiE-RSS, states {0, 1-only, 2-only, both}, β_l ~ N(0, U_s), likelihood z ~ N((I₂⊗R̃)b, V⊗R̃), R̃ = (1−η)R + ηI, V from ρ̂. With diag R = 1 the SER is a bivariate normal-means problem (no R⁻¹).
  - EB: per effect and per trait scale σ²_lt by exact R-Brent (keep-old, null check), coordinate-wise; fused Triton kernel (`famA/ser_kernel.py`, checked against the torch path to 1e-7).
  - η estimated jointly inside IBSS: after each sweep, η maximises the ELBO given q(b) using the eigen-basis of R (thin SVD for genotype factors, so the p − n_ref null-space directions carry eigenvalue η).
  - Outputs per DESIGN §5 A: a_l, w_l, p̃¹_l, p̃²_l from the fitted q (state posteriors × Gaussian effect posteriors, bivariate rectangle probabilities in `famA/bvn.py`) with τ = (6.29, 5.26) and 0.2-power thresholds (4.61, 3.58); P_S, P_D, P_W, s via `eval.adapters.inclusion_exclusion`; exclusion probabilities E₁, E₂; per-trait PIPs; variable credible sets.
- `famA/method.py`: `JointSusieMethod` (names `famA_joint_susie[_rho][_eta]` for the ablation ladder).

## 2. Identity tests (all numbers from files in `reports/famAG_M3/`)

Loci: 140 windows of real 1000G EUR LD (503 EUR samples, pgenlib from `data/processed/1kg/chrNN.pgen`, biallelic SNVs, single-record positions, MAF ≥ 0.01, MHC excluded), p ∈ {200, 500, 1000, 2000}, 0–3 causal variants per trait with |λ| log-uniform in [4, 25], z = Rλ + Gᵀu/√n (exact R covariance), n ∈ {2k, 20k, 200k}; 31 loci with factor LD (X float32), 25 "mismatch" loci (z from the LD of a random half-sample, fit with full-sample LD). Two traits per locus → **280 SuSiE fits**.

**G vs susieR 0.14.2 `susie_rss(z, R, n, L=10)`** (`identity_G/summary_*.json`):

| LD dtype on GPU | max \|ΔPIP\| | median | fits with \|ΔPIP\| ≥ 1e-3 | max \|Δα\| | same #iterations | same convergence | identical CS | CS identical up to α-ties |
|---|---|---|---|---|---|---|---|---|
| float64 | 6.7e-8 | 9.6e-11 | 0/280 | 3.3e-7 | 280/280 | 280/280 | 279/280 | 280/280 |
| float32 | 6.5e-5 | 6.3e-9 | 0/280 | 7.7e-5 | 280/280 | 280/280 | 280/280 | 280/280 |

The single strict CS difference is a tie: two variants in perfect LD with identical α (to 1e-16) at the 95 % coverage boundary; rounding picks a different member. Mismatch loci: max ΔPIP 8.9e-8 (fp64). susieR raised no errors on these loci.

**End-to-end coloc-SuSiE** (GPU SuSiE ×2 + GPU bf_bf + adapter vs R `susie_rss` + `coloc.susie(p12 = 5e-6)`, coloc.abf fallback, 140 loci, 37 fallbacks): fallback decisions agree 140/140; max |Δs| = |ΔP_S| = |ΔP_D| = 4.2e-7 (`identity_G/coloc_summary.json`). bf_bf and coloc.abf alone agree with R coloc 5.2.3 to < 1e-10 (`tests/famG/test_coloc.py`).

**A vs mvsusieR 0.3.0 `mvsusie_rss`** with η = 0, ρ = 0 and the same fixed mixture prior (U₁ = diag(25,0), U₂ = diag(0,25), U_both = diag(25,25), weights 0.375/0.375/0.25, no null weight, tol 1e-4 with mvsusieR's convergence rule), 60 1000G loci (p 200–1000, float64 PSD R) (`identity_A/`):

| A LD dtype | max \|ΔPIP\| | max \|Δα\| | max \|Δ state posterior\| | same #iterations |
|---|---|---|---|---|
| float64 | 7.7e-14 | 7.8e-14 | 5.3e-14 | 60/60 |
| float32 | 2.8e-4 | 2.4e-4 | 6.5e-3 | 57/60 |

Both meet the < 1e-2 criterion. **Why the null state cannot be matched with null_weight > 0** (`identity_A_nullweight02/`: max ΔPIP 0.54): mvsusieR computes the variable log-BF with mashr's `compute_alt_loglik_from_matrix_and_pi`, which renormalises the *non-null* mixture weights, so `null_weight` never enters α or the IBSS; it only appears in the reported `posterior_mixture_weights`. With null_weight = 0.2 mvsusieR also printed 134 "ELBO decreased" warnings over the 60 loci (none with null_weight = 0). JointSuSiE's null state is a proper prior state, so for π₀ > 0 the two models differ by construction; with π₀ = 0 they are the same model and agree to 1e-13.

**fp32 vs fp64 (DESIGN §7.1 item 10)**: G: max ΔPIP vs R is 6.5e-5 (fp32) against 6.7e-8 (fp64), so fp32–fp64 < 1e-4. A with the default configuration (EB, tol 1e-3) on the 140 identity loci: max |PIP_fp32 − PIP_fp64| = 4.0e-5 (0 loci > 1e-4), max |ΔP_S|, |ΔP_D| = 2.2e-6, same iteration counts. Under the tighter mvsusieR tolerance (1e-4) fp32 ELBO noise changes the stopping iteration in 3/60 loci (ΔPIP up to 2.8e-4).

## 4. Speed

All timings ran while other agents kept the GPU at 90–100 % utilisation and the node load at 30–36 (recorded in each JSON). They are lower bounds for an idle machine; the exclusive timing protocol of DESIGN §7.7 (machine lock, 3 repeats) still has to be run at M4.

susieR 0.14.2, single-threaded OpenBLAS, 8 loci per p, one trait: median **0.34 s (p = 1000), 1.60 s (3000), 3.54 s (5000)** per fit.

G, float32 LD, one-trait fits, loci/s (fit only; with LD read from disk in brackets; median of 3 repeats):

| p | dense, 1 batch of the set | dense, 4× larger batch | factor X (n_ref = 503), 4× batch | speed-up vs 1 susieR thread (dense, large batch) |
|---|---|---|---|---|
| 1000 | 53 (51) | 132 (117) | 103 (100) | ~45× |
| 3000 | 34 (24) | 55 (34) | 29 (28) | ~88× (fit), ~55× (with I/O) |
| 5000 | 14.5 (8.5) | 18 (10) | 12 (12) | ~64× (fit), ~36× (with I/O) |

For comparison, an ideally scaling 64-core susieR run gives about 190, 40 and 18 fits/s. **G is therefore about 0.6–1.4× a perfect 64-core CPU run, not 10×.** At p = 5000 the dense path is limited by moving the 100 MB LD matrix per locus from host to GPU. The factor path (n_ref = 503 here, 150 for pool-B references) removes most of that I/O. A tail locus that needs 59 iterations sets the batch time at p = 1000.

JointSuSiE, float32, both traits jointly, loci/s: dense 16.5 (p = 1000), 5.6 (3000), 7.5 (5000); factor 11.3, 3.2, 3.1. With η estimation (factor): 1.4–2.0 loci/s, because the per-locus float64 SVD/eigendecomposition runs one locus at a time in Python. For the mvsusieR comparison, mvsusie_rss took 55 s single-threaded for the 60 identity loci (0.9 s/locus at p ≤ 1000). JointSuSiE fitted the same loci in 6–9 s on the busy GPU.

## 5. Deviations from DESIGN
1. Purity of credible sets with more than 100 members is exact. susieR samples 100 members with R's RNG, which cannot be reproduced outside R.
2. A uses R̃ in both the mean and the covariance (Family B's convention). The DESIGN wording for A does not fix this. The layer-E reference-size variance term is not implemented.
3. A's power events use the own effect β (z-scale noncentrality), not the marginal μ = (Rβ)_j. E₁/E₂ use the 0.2-power thresholds (§5 A); §5 layer D writes τ₂. Both are flagged in `src/famA/README.md`.
4. The state prior π is fixed at (0.25, 0.25, 0.25, 0.25), with no EB yet. ρ_u = 0.
5. The coloc.abf fallback inside G uses p12 = 5e-6 (coloc.abf's default is 1e-5).
6. `runtime_s` per locus = batch wall time / number of loci (amortised).

## 6. Open issues
- **Speed of A with η**: batch the SVD/eigh (fp32 `torch.linalg.svd` on `(B, n_ref, p)`), or estimate η from the factor directly. This is the main bottleneck for the +η ablation rung.
- **G throughput is only ~1× a 64-core susieR.** Options: (a) pinned or asynchronous host→device LD transfer overlapped with compute; (b) factor LD wherever n_ref < p (I/O 10× smaller); (c) CUDA graphs or `torch.compile` for the ~50 remaining small kernels per SER; (d) send straggler loci (> 20 iterations) to a separate pool so they do not hold a whole batch. None of these change results.
- Timing needs the exclusive-lock protocol on an idle GPU (§7.7), plus the p = 500/2k/10k scaling points.
- `src/famG/locus.py` is a stub LocusData. Both Methods already work with `eval.io.LocusData` (duck typing), so the stub can be removed once the harness is used.
- A's EB uses coordinate-wise Brent per trait. Joint 2-D optimisation and EM for π are untested alternatives.
