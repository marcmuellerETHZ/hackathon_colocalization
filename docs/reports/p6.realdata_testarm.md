# p6.realdata_testarm: real-data test-arm builder (R2, R3b, R4b)

Date: 2026-10-27. Branch `p6-realdata-testarm`, based on master 606d429.

No test-split summary statistics, LD or locus sets were read or built. The frozen test ID lists were read for identifier columns and hashes only. The new metadata files were written from gene and credible-set metadata, the same inputs the M3 freeze read. Every end-to-end check used validation loci.

## 1. Result

`data.real.extract:build_test_arm` is implemented, guarded and tested. On P3-14-size validation ID lists, it reproduces real_locus_sets@2 exactly.

I recommend that real arms enter the test run (P3-26), with this methods-file entry:

```yaml
real_data_arms:
  builder: "data.real.extract:build_test_arm"
```

## 2. Interface (matches p6-dryrun `src/eval/testrun.py`, not edited)

`testrun._build_real_test` calls `builder(real_spec, data_dir/"real", workers=max(4, cores//2))`.

**Entry-point form.** When the first argument of `build_test_arm` is a mapping (`real_spec`), it dispatches to `build_test_arms(spec, out_dir, workers=)`:
- It builds R2, R3b and R4b from the frozen sub lists `pairs/<arm>_test_ids_sub_v1.tsv` (P3-14 sizes, P3-24 seeds).
- It refuses if `spec[arm]["n"]` differs from the list size (800 / 1,237 / 600).
- It returns `real_R2`, `real_R3b`, `real_R4b_insample` and `real_R4b_reference`, each as `{path, ids, …}`:
  - `real_R4b_insample` is the PC-adjusted GEUVADIS in-sample LD;
  - `real_R4b_reference` is the NFE-minus-GEUVADIS reference LD.
- It also returns `real_R4b_insample_raw` (sensitivity). testrun ignores it.
- `ids` lists the loci actually written. A pair with fewer than 2 shared variants is dropped, as in train/valid, and listed in `failed_ids`.

**Per-arm form.** `build_test_arm(arm, id_list_path, out_dir, workers=16, mode="test"|"valid")`.

**Identity with train/valid.** Extraction uses the train/valid function `extract_pair`, so these are unchanged:
- harmonisation and variant set;
- LD panels and modes;
- per-window P3-1 ρ̂ computed with each mode's own LD;
- trait types and `ld_role`;
- `boot_unit` (R3b: the FinnGen CS id `fg_cs_id`; R2/R4b: the LD block).

**Attributes added after extraction:**
- What `rho_update` wrote to valid loci: `rho_hat_pair`, `rho_se_pair`, `rho_se_pair_win`, `rho_pair_n_windows`, `rho_pair_n_clusters`. These are the cohort pair's train pooled estimate, read as exact float64 from `locus_sets/rho_v2.parquet` (@2).
- P3-23(b), new: `donor_disjoint` (bool) and `rho_sens_zero`, which is 0.0 for donor-disjoint pairs and NaN otherwise. A pair is disjoint if its two datasets differ and are not in the same `SAME_DONOR_POOLS` set. Every R2/R3b/R4b pair is disjoint.

**Test lock.** This follows the sim.testset pattern:
- **Parent check:** `has_test_access()` must hold and `scripts/eval_test.py` must be on the call stack.
- **Worker check:** every spawned worker re-checks `has_test_access()` before any test row. An access error is raised, never logged as a per-locus failure.
- **Hash checks:** the ID list must match its frozen sha256, and the metadata must match `configs/real_test_meta_v1.sha256`.
- **Output location:** anywhere inside `data/processed/real/` is refused.
- **Start method:** workers use `spawn`, because the test run is multi-threaded.

## 3. Missing columns of the frozen lists: derived without test data

**The task's premise does not hold.** `<arm>_candidates.tsv` holds train+valid rows only (`pairs.write_arm`); test rows were written as identifiers only. So the columns could not be read from the M3 tables.

**What extraction needs beyond the identifiers:**
- `gene_name`, `block_id` (`boot_unit`) and `lead1`/`lead2`, for all arms;
- `fg_region` and `fg_cs`, for R3b.

**How they were derived.** `src/data/real/test_meta.py` re-runs the M3 selection code: `eqtl_gene_cs`, `build_r2`, `r3b_prefilter` and `build_r4b`. These read gene tables and credible-set metadata only. The R3b LD filter is not re-run: the R3b rows are the pre-filter rows restricted to the frozen ids.

**Verification** (job `p6rt_test_meta_r2`, commit f241c4e, `data/processed/real_testmeta_v1/test_meta_v1.verify.json`):

| Check | Result |
|---|---|
| Rebuilt train+valid rows, R2 and R4b | byte-identical to `R2_candidates.tsv` and `R4b_candidates.tsv` |
| Rebuilt train+valid rows, R3b | identical on all 28 pre-LD columns of `R3b_candidates.tsv` |
| Frozen sha256 files reproduced from the rebuilt test rows | 6 of 6 (R2 546b139b…/9f1501a9…, R3b 769060f6…, R4b 71ebdc48…/44c4e1a2…) |

**Outputs.**
- Files: `<arm>_test_meta_v1.tsv`, with rows equal to the frozen sub list in the same order. They contain no p-values, z-scores, CS members or LD.
- Location: moved at the PI's request to `data/processed/real_testmeta_v1/`, contents unchanged, and registered as **real_test_meta@1** (full checksum f6dbff51…).
- Hash file: committed as `configs/real_test_meta_v1.sha256`.
- `orch artifact verify real_locus_sets --fast` gives **OK for @2**. @1 was already stale and mismatched.

## 4. End-to-end test on validation ID lists

**Setup.**
- Command: `python scripts/real/check_testarm_valid.py --out data/processed/real_testarm_valid_check_v1 --workers 4` (job `p6rt_valid_check_r4`, commit aa647c9, exit 0).
- ID lists: in the frozen format, at P3-14 sizes (R2 800, R3b all 1,203, R4b 600), drawn with `rng(20261029, "real_testarm_valid_check", arm)`.
- Builder: `build_test_arms(mode="valid")`.
- Comparison: every locus of all 5 files against real_locus_sets@2.

**Result: 5 of 5 sets OK, with 0 mismatches.**

| Set | Loci written / compared | Mismatches |
|---|---|---|
| R2 | 800 / 800 | 0 |
| R3b | 1,203 / 1,203 | 0 |
| R4b in-sample (pcadj) | 600 / 600 | 0 |
| R4b reference | 600 / 600 | 0 |
| R4b raw | 600 / 600 | 0 |

- Identical: written ids; variant ids, positions, z1/z2, beta/se, n, MAFs and `X_ref` (exact array equality); and every standard and extra @2 attribute, including `rho_hat`, `rho_se`, `rho_hat_pair` & co, `boot_unit`, `fg_cs_id` and `ld_role`. The maximum float difference is 0.0.
- The only added attributes are `donor_disjoint` (true for all loci) and `rho_sens_zero` (0.0 for all loci).
- The output is registered as real_testarm_valid_check@1 (fast checksum fc478a04…). It is 3.9 GB and can be deleted after the freeze.

**Timing.** The build took 1,412 s with 4 workers, about 5,600 core-s. In the test run, at 32 workers, expect about 3–5 min and about 4 GB of disk.

**Tests.** `python -m pytest -q tests/data_real` (job `p6rt_tests_r2`, aa647c9) gave **41 passed**. That is 28 old tests plus 13 new ones in `tests/data_real/test_real_testarm.py`:
- refusal without access, in both the per-arm and entry-point forms;
- the parent check needs `eval_test.py`, which is the known answer for a fake `scripts/eval_test.py`;
- the worker check, and that access errors are not swallowed;
- refusal of an unfrozen ID list;
- validation-mode split and format checks, and that output inside `data/processed/real` is refused;
- refusal of a spec size mismatch;
- entry-point dispatch, keys and signature, matching testrun's call;
- the donor-disjoint known answers;
- toy verification of `test_meta`, including tamper detection;
- the frozen metadata hash check;
- valid-mode equality with @2 on R3b and R4b loci.
