under the natural class distribution of world L0*. Here it is computed for the final checkpoint on l0star_v2.

### Robustness requested by the PI: LD blocks and the W term

The set has 2,000 loci (500 each of S, D, W, G) from 111 LD blocks (the anchor block in truth `block_id`).

| class | loci | LD blocks | natural share used | contribution to C1 (share × class KL) |
|---|---|---|---|---|
| S | 500 | 106 | 0.0524 | 0.00125 |
| D | 500 | 94 | 0.0627 | 0.00102 |
| W | 500 | **10** | 0.7927 | 0.00136 (**24%** of C1) |
| G | 500 | 73 | 0.0921 | 0.00201 |
| total | 2,000 | 111 | 1 | 0.00563 |

- **Why the shares are renormalised.** U is too rare for the stratified set: its natural share, 0.0070, is not
  represented. The shares of S/D/W/G are renormalised over those four classes, as P3-4 specifies.
- **Why W comes from only 10 blocks.** W is 79% of candidate loci, so `build_set` fills its 500 W loci within the
  first few window visits. The W class-mean KL (0.0017) therefore rests on few LD contexts, and the block
  bootstrap resamples those 10 blocks.
- **The W term does not decide the result.**
  - The other three terms sum to 0.0043.
  - The pass would survive the W class KL being 11× larger: (0.02 − 0.0043) / 0.793 = 0.0198 vs 0.0017.
  - The bootstrap upper bound, 0.0087, already includes the variation between W blocks.
  - Each of the four class terms is between 0.0010 and 0.0020, so no single class drives the pass.
- **B's Monte Carlo noise is negligible.** Its second-order KL floor is 3 × 10⁻⁶ (B's max replicate SE 0.0024).

## What was run

1. **Truth isolation (P3-21) and the true-ρ input check**, committed at 76ad32b.
   - Evaluation code that reads truth moved to `scripts/famC_eval/c1_eval.py`.
   - `src/famC/c1.py` only trains and predicts; it reads no truth. `tests/eval/test_truth_isolation.py` passes.
   - `famC.features.extract` asserts that a batch carries no true `rho`. Network inputs are rho_hat and rho_se
     only. In L0* sets, rho_hat equals the true ρ by the world's definition, and training feeds it exactly as the
     set gives it to methods.
   - `simadapter` now passes the mismatch level to `rho_hat_for`, as `sim.train_api` does (main-task path).
   - Tests: `python -m pytest -q tests/famC tests/eval/test_truth_isolation.py` → 26 passed (job
     `famC_c1_tests_r1`). The new `tests/famC/test_c1_stream.py` checks four things:
     - stream inputs equal the `build_set` LocusData inputs through the Method path;
     - the stream settings match l0star;
     - extract refuses a batch carrying the true ρ;
     - the logit-correction switch works.
2. **Training** (job `famC_c1_v2_train`, done; 168 min GPU; ≤ 4.7 GB VRAM). The command was
   `python -m famC.c1 train --run c1_v2 --n-train 16000000 --batch 512 --lr 5e-4 --eval-at 1000000,2000000,4000000,8000000 --per-seg 128 --segs-per-window 32 --max-hours 2.8`.
   - The spec is l0star_v2's, through `sim.l0star` on train-split windows only:
     - p = 20, η = 1e-3, R̃ given as the LD;
     - ρ uniform over (0, ±0.3, ±0.5, ±0.8);
     - N 100k / 1k, gwas × mol;
     - windows with ≥ 200 variants;
     - the natural class mixture.
   - Loss: unweighted cross-entropy, so the softmax is used as is, with no logit correction. The independent
     verifier confirmed this scoring (reviews/p5_verify_famC_scoring.md).
   - The architecture is the C0 model: 1.04 M parameters, with the same hyper-parameters as the c1_long pilot.

   - 3,560 window visits; 14,412,288 loci; 1,300–1,450 loci/s on the shared GPU.
3. **Evaluation** (job `famC_c1_v2_eval_l0star_v2_r3`, priority 11, done). The command was

## Limits

- **One training seed and one run.** The CIs cover locus and block sampling of the evaluation set, not training
  variance.
- **Only 10 LD blocks in the W stratum** (see above). This is a property of the set, which was not changed.
- **C1 tests C in B's own world.** It does not show that C is better than B or A on the realistic grid; that is
  C2. The main-task C models so far are development models: 74 k records from a pre-M3.5 simulator.

## Follow-up 2: plan for a proper C2 (after the 21:00 decision; nothing started)

C2 (DESIGN §5 C) has two conditions:
- realistic-grid AUPRC ≥ the best of A/B, at equal or better *recalibrated* ECE;
- a train-region vs validation-region gap < 0.02.

C must also beat the LightGBM floor and its own no-LD ablation. Failing C2 demotes C to a fast pre-filter.

| step | what | budget (measured rates) |
|---|---|---|
| 0. throughput check | `sim.train_api.bench_multi` on CPU (16 cores) vs 1 GPU worker. This picks the device for generation; small-matrix simulation should run on CPU if competitive. | 15 min, 1 job |
| 1. train data `train_v1` | `famC.gen_shards` on the committed simulator: train windows, seed 20261030, L6 and L6c held out, natural class mixture, 2 noise draws per candidate (C-T6). **Target 600 k records**, about 78 GB at 129 KB/record (measured on train_dev_snap1), registered as an artifact. | M3.5 rate 10–13 loci/s per GPU worker: 4 workers × ≤ 3 GB ≈ 160 k/h, so about **4 h**. Less if the CPU path is faster. |
| 2. validation data `valid_v1` | Validation windows, seed 20261029, all levels including L6, acceptance S 1 / D 1 / U 1 / G 0.5 / W 0.3, 30 k loci. Runs in parallel with step 1. | ~1.3 h on 1 worker |
| 3. network | `famC.train_main` on train_v1, learning curve at 75 k / 150 k / 300 k / 600 k records, about 8 passes over the largest. Reports train-region vs validation gap at each size. | ~1,150 loci/s, so ≈ **1.5 h GPU**, ≤ 6 GB |
| 4. floor and ablation | LightGBM floor on an equal 600 k (feature cost 22–44 ms/locus on GPU SuSiE ≈ 5.5 h; or on the 150 k subset matched to the network's 150 k point, ≈ 1.4 h). No-LD ablation with the network's schedule. | ≈ 1.4–5.5 h + 1.5 h GPU |
| 5. C2 evaluation | Harness on the M4 main subsample with the final network, then one joint benchmark reusing A's, B's and the baselines' runs (paired, block bootstrap, recalibrated ECE). | 20 min GPU + 25 min CPU |

- **Total.** About 8–12 h of GPU time (generation can move to CPU if step 0 favours it) and 10–12 h of wall
  clock, so overnight.
- **Recommended default.**
  - Start steps 0–2 after the 21:00 decision only if the PI keeps C as a research arm. C is not a test-run

  - Otherwise record C as "C0 + C1 passed, C2 not run". Its provisional M4 numbers above qualify it as a fast
